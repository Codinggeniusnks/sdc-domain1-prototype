## 2. P0 Flaw: Silent Grouped Cross-Validation Failure in `execute_runpod_experiments.py`

### Mechanism of the Failure
In [`scripts/execute_runpod_experiments.py`](file:///C:/Users/LENOVO/.gemini/antigravity/scratch/sdc-domain1-prototype/scripts/execute_runpod_experiments.py) (lines 70–86):
```python
def assign_clusters(dataset: list[dict]) -> list[str]:
    clusters = []
    for r in dataset:
        tier = r.get("source_tier", "BRONZE")
        if tier == "GOLD":
            meta = r.get("metadata", {})
            masco = str(meta.get("masco_code", "")).strip()
            if masco:
                clusters.append(f"REAL_{masco[:4]}")
            else:
                clusters.append(f"REAL_FW-{r.get('id', 'fw')}")
```
In [`data/processed/dataset_v4_clean_multisource.json`](file:///C:/Users/LENOVO/.gemini/antigravity/scratch/sdc-domain1-prototype/data/processed/dataset_v4_clean_multisource.json), records do not possess a nested `metadata.masco_code` dictionary. The actual occupational codes reside in top-level fields `occupation_group` and `occupation_family`.

As a consequence:
1. Every real GOLD record fell into the fallback branch: `REAL_FW-{r['id']}` (e.g., `REAL_FW-masco-2512-01`, `REAL_FW-esco-04fd8670`).
2. The pre-computed [`artifacts/cv_split_manifest.json`](file:///C:/Users/LENOVO/.gemini/antigravity/scratch/sdc-domain1-prototype/artifacts/cv_split_manifest.json), however, was generated by [`scripts/execute_training_cv_protocol.py`](file:///C:/Users/LENOVO/.gemini/antigravity/scratch/sdc-domain1-prototype/scripts/execute_training_cv_protocol.py) using `REAL_{occupation_group}` keys (e.g., `REAL_2424`, `REAL_2512`, `REAL_2511`).
3. When `execute_runpod_experiments.py` assigned validation records (`val_indices = [i for i, c in enumerate(clusters) if c in val_clusters]`), **zero GOLD records matched any validation fold**.

### Measured Consequence
| Metric | Intended Manifest Protocol | Actual RunPod Script Execution |

| **Fold 0 Validation Set** | 14 Gold + 63 Synth (77 total) | **0 Gold + 42 Synth (42 total)** |

## 3. P0 Flaw: Unauthorized Candidate Architecture Substitutions

The experimental plan approved by research leadership required evaluating:
- **Candidate B**: PyTorch Multi-Task Neural Network (`SkillsPredictorNN`).
- **Candidate C**: Pretrained Bi-Encoder (`sentence-transformers/all-MiniLM-L6-v2`) dense semantic representation.

### Actual Implementations
1. **Candidate C**:
   In `execute_runpod_experiments.py` lines 176–187:
   ```python
   svd = TruncatedSVD(n_components=min(64, X_tr.shape[1] - 1), random_state=42)
   X_tr_dense = svd.fit_transform(X_tr)
   ```
   Candidate C was implemented using **TruncatedSVD on TF-IDF matrices** (standard Latent Semantic Analysis). No transformer bi-encoder or neural language model was ever downloaded or evaluated.
2. **Candidate B**:
   In lines 221–236, Candidate B was implemented using `sklearn.neural_network.MLPClassifier` with independent single-task heads. No shared multi-task backpropagation or PyTorch architecture was used.

**Finding**: The report's claim that *"Pretrained bi-encoders fail to generalize on specialized competency taxonomies"* is scientifically unfounded because a pretrained bi-encoder was never tested.

## 5. P1 Flaw: Protocol B and Protocol C Composition & Non-Independence

### Protocol B Truth Audit ($N=63$)
The previous report described Protocol B as *"100% genuine Malaysian job postings, competency standards, and ESCO/OpenAlex real profiles."*

Independent verification of all 63 records reveals:
- **ESCO v1.1 (European Commission Taxonomy)**: 34 records (**54.0%**).
- **Public Competency Standard Descriptors**: 16 records (**25.4%**).
- **MASCO 2020 & TalentCorp MyCOL Profiles**: 9 records (**14.3%**).
- **Synthetic Benchmark Personas**: 4 records (**6.3%**).
- **Malaysian Job Postings (JobStreet / LinkedIn)**: **0 records (0%)**.
- **OpenAlex Scholarly Literature**: **0 records (0%)**.

**Finding**: Protocol B contains **zero live Malaysian job postings** and **zero OpenAlex records**. Over half of Protocol B consists of European occupational taxonomy crosswalks.

### Protocol C Nesting and Leakage ($N=25$)
1. **Complete Nesting**: All 25 records in Protocol C (`unseen_occupation_test_set.json`) are a **strict subset** of Protocol B. Protocol C is not an independent holdout set.
2. **Occupational Group Overlap with Training**:
   - 8 of the 25 records in Protocol C share their exact 4-digit `occupation_group` with records present in training (e.g., MASCO 2133, 2422, 2424, 2412, 4222, 4311).
   - 23 of the 25 records share their 2-digit major occupation family with training records.
   Protocol C is therefore only partially unseen at the job title level, not at the occupational family level.

## 6. P1 Flaw: Calibration Leakage & Distortion

In `CalibratedClassifierCV(cv=3)`:
- The training records were expanded by repeating GOLD records 3 times (`reps = 3`).
- Because `StratifiedKFold(3)` splits record indices blindly, **identical repeated instances of the same GOLD record were simultaneously present in the fitting fold and the calibration fold** (verified 6 duplicate key leaks across the 3 folds).
- Platt scaling overfit to repeated instances, actively distorting probability outputs and degrading the true out-of-fold ROC AUC from 0.7866 down to 0.6897.
